# 기존 테스트 콘텐츠 보강 기록

문서의 경로는 저장소 루트 기준이다. 이후 폴더 정리로 실행 코드는 `assets/js/`, 스타일은 `assets/css/`, 질문·결과 데이터는 `data/tests/`, 소개·해설은 `data/content/`로 옮겼다. 아래 보호 파일 비교는 콘텐츠 보강 당시의 기록이며, 폴더 이동 이후에는 참조 경로를 변경하고 전체 자동 검사를 다시 수행했다.

## 변경 범위

새 테스트를 만들지 않고 기존 50개 테스트 모두에 고유한 결과 후속 읽을거리를 추가했다. 각 테스트는 짧은 소제목과 본문으로 구성된 섹션 3개를 가지며, 각 섹션은 2~4문장이다. 본문 추가 분량은 테스트당 322~382자(공백·문장부호 포함, 소제목 제외)다.

유형별 특징을 다시 나열하는 대신 구체적인 장면, 대화 예시, 작은 활동을 담았다. 장거리는 연락 기대·이동 부담·장거리 계획, 직장은 업무 인수인계·역할·중간 공유를 다룬다. 날씨·동물·비밀요원 등 재미형 콘텐츠는 캐릭터와 가상 상황을 가볍게 확장한다. 기존 결과 참고 문구는 유지했다.

## 수정 및 추가 파일

| 파일 | 역할 |
| --- | --- |
| `data/content/test-guides.js` | 50개 테스트의 고유 해설과 주제별 관련 테스트 3개씩 관리 |
| `assets/js/test-runner.js` | 해설 DOM 구성, 지정한 관련 테스트의 실제 링크 표시 |
| `test.html` | 해설 데이터 로드 및 결과 카드 아래 해설 영역 추가 |
| `assets/css/test.css` | 기존 색상·글꼴을 사용하는 짧은 해설 섹션 스타일 |
| `data/content/test-introductions.js` | 기존 첫 소개 문단을 모두 보존하고 6개 테스트의 상황 설명 보완 |
| `index.html` | 기존 전체 목록을 유지하면서 큐레이션 3개 그룹, 링크 12개 추가 |
| `assets/css/style.css` | 홈 큐레이션의 텍스트 목록 및 모바일 배치 |
| `tests/content.test.js` | 전체 해설·문장 중복·유사도·관련 링크·큐레이션 검사 |
| `tests/browser-smoke.js` | 기존 브라우저 검사에 전체 테스트 해설과 큐레이션 검증 추가 |
| `docs/content-quality.md` | 관리 방법과 검증 결과 기록 |

소개를 보완한 테스트는 장거리 연애, 경쟁심, 사회성, 숨은 강점, 직장 이미지, 정이 많은 정도다. 기존 첫 문단과 질문·선택지에 쓰이는 설명 데이터는 수정하지 않았다.

## 콘텐츠 관리 방법

`data/content/test-guides.js`의 `TEST_GUIDES`는 기존 카탈로그의 slug를 키로 사용한다. 값은 `[소제목, 본문]` 세 쌍이다. 해설은 답변이나 결과 유형을 입력받지 않으며, 결과 카드 아래에서 해당 주제를 넓혀 읽도록 작성한다. 시작·문항 화면에서는 상위 결과 화면과 함께 숨겨진다.

같은 파일의 `TEST_RELATED`에 관련 테스트 slug 3개를 순서대로 지정한다. 카탈로그의 URL과 제목으로 `<a href>`를 만들어 자기 자신이나 중복 항목이 표시되지 않게 한다. 지정 데이터가 없으면 기존 카테고리 추천 방식으로 보완한다.

소개는 계속 `data/content/test-introductions.js`에서 관리한다. 홈 큐레이션은 `index.html`의 실제 HTML 링크이므로 검색·필터·페이지네이션에 의존하지 않고 탐색할 수 있다. 새로운 프레임워크나 빌드 단계는 도입하지 않았다.

편집할 때는 한 가지 장면을 자세히 다루고, 해당 유형의 특징이나 장단점을 다시 설명하지 않는다. 진단·연구를 주장하는 표현을 사용하지 않으며, 각 테스트만의 구체적인 소재를 남긴다.

## 홈 큐레이션

- **연애할 때 나는 어떤 사람일까?**: 행복한 연애 방식, 오래 이어지는 사랑, 숨기고 싶은 모습, 장거리 연애
- **회사에서의 나**: 사회생활 눈치, 못 견디는 동료, 직장 이미지, 경쟁심
- **의외의 내 모습**: 날씨 성격, 비밀요원, 인터넷 밈, 인생 다시 시작하기

각 그룹은 기존 테스트 4개를 연결한다. 전체 테스트 50개와 기존 오늘의 테스트·검색·카테고리·페이지네이션을 유지했다.

## 검증 결과

다음 명령을 저장소 루트에서 실행해 모두 통과했다.

```text
node tests/content.test.js
node tests/seo.test.js
node tests/routing.test.js
node tests/analytics.test.js
node tests/browser-smoke.js
```

- 해설 50개, 소제목 150개, 본문 150개, 문장 353개를 검사했다. 추가 해설 사이에 동일한 소제목·문단·문장이 없고, 같은 테스트의 기존 결과 문장을 그대로 재사용한 해설도 없다.
- 서로 다른 테스트의 문단을 정규화한 뒤 연속 5글자 집합의 Jaccard 유사도를 비교했다. 최고치는 4.1%다. 이 수치는 표현 유사도 검사이며 내용의 의미를 완전히 판정하는 지표는 아니다. 주제별 소재와 결과 설명의 중복 여부는 편집 검토를 함께 거쳤다.
- 관련 링크 150개는 모두 기존 테스트이며 각 페이지에 서로 다른 링크 3개가 연결된다. 홈 큐레이션 링크 12개도 기존 URL·제목과 일치한다.
- Chrome 로컬 브라우저 검사 55건을 통과했다. 홈 390px·1200px, 전체 50개 테스트 390px, 장거리·직장 갈등·날씨 테스트 1200px다. 결과 도달, 해설 3개 표시 및 위치, 관련 링크, 결과 화면 가로 넘침, 재시작 후 해설 숨김을 확인했다.
- 기존 검사는 50개 테스트의 메타데이터·slug/숫자 ID 경로·오류 처리·56개 사이트맵 URL·GA4 이벤트·재시작·Kakao 공유 호출을 검증했다.
- Git HEAD와 줄바꿈 형식을 정규화해 비교했다. `*-data.js` 50개와 카탈로그·로더·SEO·포커스·분석·공유/홈 동작·사이트맵·robots·404·도메인 설정을 포함한 61개 보호 파일이 동일하다. `assets/js/test-runner.js`의 화면 전환·질문·점수·결과 판정·재시작 함수 부분도 동일하다.
- HTML head는 `data/content/test-guides.js` 로드 한 줄 외에 동일하다. title, description, canonical, OG, GA4 로드, Kakao SDK, AdSense 삽입 코드를 보존했다. noindex 처리를 담당하는 SEO 및 오류 코드도 보존했다.
- 변경 JavaScript 구문 검사와 `git diff --check`를 통과했다.

## 배포 후 수동 확인

이 작업은 로컬 소스 수정이며 실서비스 배포는 수행하지 않았다. 브라우저 자동 검사에서는 실제 GA4 전송 및 외부 SDK·광고 스크립트를 차단하므로 다음 항목은 운영 사이트에서 확인한다.

- iOS Safari·Android Chrome에서 긴 결과의 줄바꿈, 읽기 간격, 다시하기·관련 링크 터치 동작
- 실제 Kakao 앱으로 공유 전송 및 공유된 링크·미리보기
- GA4 실시간/DebugView에서 `test_view`, `test_start`, `test_complete`, `test_share` 수신
- AdSense 스크립트 로드, 광고가 표시될 때 해설과 버튼의 배치
- 배포 후 캐시가 갱신되어 `data/content/test-guides.js`가 정상 로드되는지

콘텐츠 보강은 애드센스 재심사 통과를 보장하는 판정이 아니다.
